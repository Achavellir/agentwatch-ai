See what your AI agent actually did

AgentWatch reads an agent's recorded tool calls, checks each one against your policy, and flags sessions for a person to review, with the evidence attached. It runs locally and needs no paid API.

pip install git+https://github.com/Achavellir/agentwatch-ai

All figures come from a frozen synthetic evaluation, not production data. One of the four scenarios is benign high-volume traffic, so "flagged" never means "attack confirmed". See Synthetic results.

What it does

Policy rules

Four explicit checks: unapproved destinations, sensitive data leaving, writes or shell commands without approval, and network calls with no destination.

Anomaly score

An Isolation Forest over six per-session counts, trained on a reviewed baseline. It can add a session to review but never removes a rule finding.

Evidence reports

Offline HTML and JSON reports that link each finding to the exact events behind it. Private folders, no page content stored.

Local browser view

Upload a trace, filter findings and expand evidence in a browser tab bound to 127.0.0.1. No cloud, no CORS.

Example

Review a trace with rules only, approving one host:

agentwatch --rules-only \
  --input examples/candidate.jsonl \
  --allow-domain docs.example.com \
  --output private-data/review-1

Add --baseline examples/baseline.jsonl in place of --rules-only to include the anomaly score. Open report.html in the output folder.

Installation

AgentWatch needs Python 3.11 or later. It installs two commands: agentwatch and agentwatch-ui.

From source

git clone https://github.com/Achavellir/agentwatch-ai
cd agentwatch-ai
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -c requirements-lock.txt .

The lock file pins exact versions of numpy, scipy, scikit-learn, joblib, cloudpickle and threadpoolctl.

Known issue in v0.3.0: numpy 2.5.3 and scipy 1.18.1 have no Python 3.11 builds, so the locked install fails on 3.11. Use Python 3.12, or install without -c requirements-lock.txt. A fix with per-version pins is prepared and not yet released.

Check the install

python -m unittest discover -s tests -v
python evaluate.py
python scripts/check_installed.py

evaluate.py is the frozen regression gate: it fails if an expected detection disappears or normal alerts exceed the recorded baseline.

Quickstart

Review the bundled example trace in under a minute.

1. Rules only

agentwatch --rules-only --input examples/candidate.jsonl \
  --allow-domain docs.example.com --output private-data/review-1

No baseline is needed. Each session gets the policy findings that apply to it.

2. Add the anomaly score

agentwatch --baseline examples/baseline.jsonl --input examples/candidate.jsonl \
  --allow-domain docs.example.com --output private-data/review-2

The baseline must hold at least 30 sessions that someone has reviewed as normal. The bundled one is a demonstration, not a model of any real deployment.

3. Open the report

Open report.html in the output folder, or run agentwatch-ui --open and choose the trace file. Output folders that already exist are refused, so earlier reviews are never overwritten.

Event schema

A trace is a JSON Lines file: one object per tool call. Sessions are complete, bounded runs.

FieldTypeMeaning
event_idstringUnique per event; duplicates are rejected
session_idstringGroups events into one run
toolstringOne of read, search, http, write, shell
destinationstringHTTP(S) URL; only scheme and host are kept. URLs with credentials are rejected
bytes_sentintegerOutgoing bytes, not response size
sensitivebooleanSet by trusted application controls
approvedbooleanSet by trusted application controls

Approval and sensitivity must come from your application, never from the model's own claim about what it is doing.

{"event_id":"e1","session_id":"s1","tool":"http","destination":"https://docs.example.com","bytes_sent":125,"sensitive":false,"approved":true}

Limits: 10 MB per file on the command line, 2 MB in the browser view.

Policy rules

Four independent checks. Each finding links to the events that triggered it.

FindingFires when
UNAPPROVED_DESTINATIONA destination's hostname is not in the approved set (exact match, so lookalike hosts are caught)
SENSITIVE_EXTERNAL_TRANSFERSensitive data is sent to a host outside the approved set
ACTION_WITHOUT_APPROVALA write or shell call has no recorded approval
MISSING_DESTINATIONAn HTTP call, or any call sending bytes, has no destination

A session goes to review if any rule fires or its anomaly score is unusual. The model cannot cancel a rule finding.

Anomaly scoring

An optional second signal that looks at the shape of a whole session rather than single events.

Features

Six counts per session, each passed through log1p: tool calls, bytes sent, external calls, sensitive calls, write and shell calls, and distinct tools.

Model

scikit-learn IsolationForest with 200 trees, contamination 0.05, random seed 42 and one worker. A negative margin means unusual. It is not an attack probability.

Baseline medians in the report give context for a score. They are not a causal explanation of why a session looks unusual.

Browser view

Review a trace without the terminal.

agentwatch-ui --open

Choose a trace file, enter approved hosts, then filter findings, expand evidence and download HTML or JSON. A synthetic sample is built in. There is no machine learning in the browser view.

How it stays local

The server binds to 127.0.0.1 and checks Host, Origin and a per-process token. Uploads stay in memory, sizes and concurrency are limited, and there is no CORS or file-system route. Do not expose it publicly or through a tunnel.

The action is the same; the policy changes. The request follows no redirects, sends no credentials or cookies, caps the response at 1 MiB and saves no page content. This is a scripted integration, not an autonomous agent.

Agent integration

In development. This code is not in v0.3.0 and has been tested only with a scripted stand-in model, not a real LLM.

Record a tool call where it actually runs, with its outcome, and let your application decide what is approved.

# agent_tools.py (unreleased)
from agent_tools import PathPolicy, ToolRecorder

policy = PathPolicy(root=workspace, writable_dirs=("out",),
                    sensitive_dirs=("secrets",),
                    network_hosts=frozenset({"docs.python.org"}))

with ToolRecorder("trace.jsonl", "run-1", policy) as rec:
    read_file = rec.wrap("read", read_file,
                         describe=lambda path: {"path": path})
    http_get = rec.wrap("http", http_get,
                        describe=lambda url: {"url": url})

Outcomes

Each event gains status (ok, error or denied), seq, ts and duration_ms. Denied calls are recorded but never run, so a blocked exfiltration attempt shows as UNAPPROVED_DESTINATION with zero bytes sent.

Completeness

A sidecar file records when each session opened and closed and how many events it wrote. A check reports unclosed sessions, cut-off traces and gaps in the sequence. It cannot detect a producer that skipped the wrapper altogether.

Independent study

In development. The harness is built and tested on constructed data; no study data or results exist yet.

The question: does anomaly scoring find actionable sessions that rules miss, and is it worth the extra reviewer time?

Order of operations

Split. Whole task families go to baseline, tune or final, so related runs never straddle sets. Policy-violation families never train the baseline.

Label blind. Reviewers see events only, with no findings or scores, and mark each session normal or actionable.

Tune, then freeze. Try policies on the tune set only. Freezing pins the policy, settings and file hashes.

Score once. Scoring refuses if anything changed since the freeze and logs every run.

python independent_eval.py split --trace run/activity.jsonl --runs run/runs.jsonl \
  --study private-data/study-1 --keep-out-of-baseline controlled-violation
python independent_eval.py freeze --study private-data/study-1 --allow-domain docs.python.org
python independent_eval.py score --study private-data/study-1 --labels final.csv --output results.json

Reported per mode: true and false positives, recall and false-alert rate with 95% Wilson intervals, alerts per reviewer, reviewer agreement, analyzer time and logging completeness.

Command line

OptionMeaning
--input PATHTrace to review (JSON Lines)
--rules-onlyRun policy rules without a baseline
--baseline PATHReviewed normal sessions for the anomaly score (30 or more)
--allow-domain HOSTApproved host; repeat for each
--output DIRNew private folder for report.html and report.json

Report folders are created with mode 0700 and files with 0600. A completion marker is written only after every report finishes.

Limitations

AgentWatch reviews recorded activity. It is not a preventive control, antivirus, EDR or website scanner, and it is not production-validated.

  • Telemetry can be left out or forged by whatever produces it.
  • Baseline poisoning and drift are not solved.
  • Session counts lose the order and intent of actions.
  • The trace writer relies on the caller's permissions and a single process.
  • Other processes running as the same user, browser extensions and OS swap are outside the protection claim.
  • Passing tests does not prove security. The last dependency advisory check is dated and must be refreshed.
